# Structurer GitHub comme dépôt technique et portfolio

1. Déclencher pour README, STATUS, documentation, structure de dépôt, contribution, release ou PR.
2. Distinguer code et IaC, manuel d’exploitation reproductible, et vitrine du travail personnel.
3. Conserver installation des outils, prérequis, procédures, preuves, archives et historique : inventorier avant toute suppression ou déplacement.
4. Afficher d’abord besoin, rôle réel de l’auteur, contribution personnelle, état vérifiable et accès utiles.
5. Conserver STATUS comme source canonique d’avancement; ne pas qualifier de réel un screenshot fictif ni de vérifié un exemple.
6. Expliquer architecture, choix, démarrage et diagnostic, avec liens relatifs, textes alternatifs et commandes copiables.
7. Préparer une revue des liens et du rendu, clairement distincte des essais applicatifs. Push, publication, merge et création de PR restent soumis aux autorisations.

## Livraison

Indiquer les éléments lus, les décisions, les fichiers ou pages réellement modifiés, les contrôles effectivement exécutés et les limites. Le Skill ne crée aucun droit d'outil.
